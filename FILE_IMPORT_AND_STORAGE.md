# FILE_IMPORT_AND_STORAGE.md — импорт книг и локальные данные

Этот документ дополняет `TASK_2_REQUIREMENTS.md` техническими правилами. Приложение остаётся статическим сайтом без авторизации, backend и внешних API.

## 1. Импорт файлов

### Поддерживаемые форматы
- EPUB (`.epub`)
- Word Open XML (`.docx`)
- Plain text (`.txt`)

Legacy Word `.doc` не поддерживается в MVP. В таком случае сообщить пользователю: «Этот формат Word не поддерживается. Откройте документ в Word и сохраните его как DOCX».

### Обработка
1. Пользователь выбирает локальный файл через `<input type="file">`.
2. Проверить расширение/тип и размер (лимит по умолчанию 30 МБ).
3. Прочитать и преобразовать содержимое полностью в браузере; не отправлять файл на сервер.
4. Извлечь безопасный текст и метаданные: название, исходное имя, формат, дата импорта, число слов.
5. Не использовать `dangerouslySetInnerHTML` для непроверенного содержимого книги. При отображении хранить/показывать текст и безопасно форматировать абзацы.
6. В случае ошибок сообщить человеческим языком, что произошло и как попробовать снова.

### Библиотеки
До установки новых пакетов изучить существующий `package.json` и lockfile. Использовать совместимые и не конфликтующие зависимости. Для DOCX подходят библиотеки класса Mammoth; для EPUB — EPUB-парсер или корректное чтение ZIP-содержимого/manifest/spine. Claude должен проверить документацию выбранной библиотеки и способ её работы в браузере. Не добавлять API-ключи.

## 2. Где хранить данные

### localStorage
Использовать для небольших данных:
- настройки тренировок;
- записи результатов и сводную историю;
- список использованных ID встроенных текстов;
- последние 20 наборов игры на память (если хранение не раздувает историю);
- отметки доступности букв и дату завершения;
- небольшие метаданные/версию схемы.

Обрабатывать повреждённые/устаревшие данные безопасно: не ронять всё приложение из-за JSON.parse error; сохранить возможность восстановить или сбросить повреждённую запись с явным уведомлением.

### IndexedDB
Использовать для:
- извлечённого текста книг;
- списка книг и метаданных;
- последней позиции/главы чтения.

Нельзя сохранять целые EPUB/DOCX-файлы в localStorage. Файлы можно не сохранять как оригиналы, если сохраняется извлечённый текст; достаточно локальной библиотеки и прогресса. Если выбранная архитектура умеет безопасно хранить исходный Blob, это опционально.

## 3. Модель записи тренировки

У записей должна быть общая форма (точные типы можно адаптировать под текущий код):

```ts
type TrainingType =
  | 'reading'
  | 'schulte'
  | 'munsterberg'
  | 'memory_words'
  | 'mnemo_grid'
  | 'alphabet_association';

interface TrainingRecord {
  id: string;
  type: TrainingType;
  completedAt: string; // ISO string
  durationSeconds: number;
  result: Record<string, unknown>; // параметры/метрики конкретной игры
}
```

Предпочитать расширяемые типы и тестируемые функции сохранения. Не стирать и не переименовывать существующие ключи/поля без миграции. Добавить версию локальной схемы, если это упростит безопасные обновления.

## 4. Ежедневная блокировка букв

Хранить завершение по букве, например:

```ts
interface AlphabetLetterCompletion {
  letter: string;
  completedOnLocalDate: string; // YYYY-MM-DD
  resultId: string;
}
```

На открытии карты алфавита сравнивать `completedOnLocalDate` с локальной сегодняшней датой. Если дата отличается, буква доступна вновь. Не утверждать, что такой client-side lock является защищённым: пользователь может изменить дату устройства или очистить storage.

Активную игру хранить отдельно от завершённых отметок: целевая буква, индекс категории, текущие ответы и `startedAt`. При возобновлении вычислять время от timestamp, не обнулять его. Финальная запись/блокировка создаётся только один раз при завершении последней карточки.

## 5. Работа с таймерами

Не использовать число тиков `setInterval` как единственный источник времени. Хранить timestamp начала и вычислять:
- отсчёт: `remainingMs = max(0, deadlineMs - Date.now())`;
- секундомер: `elapsedMs = Date.now() - startedAtMs`.

`setInterval` можно использовать только для обновления отображения. При `visibilitychange`/возвращении на вкладку пересчитать состояние таймера по timestamp. Завершение сессии должно быть идемпотентным, чтобы результат не сохранялся дважды.

## 6. Приёмка локального режима

- Сайт работает без сетевых запросов за исключением загрузки самого сайта/статических ресурсов.
- После обновления страницы остаются история, настройки, использованные встроенные тексты, импортированные книги и ежедневные отметки букв.
- Очистка данных сайта может удалить локальные данные; предупредить пользователя об этом в интерфейсе прогресса или настройках.
