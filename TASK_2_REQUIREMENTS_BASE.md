# TASK_2_REQUIREMENTS.md — требования к следующему этапу приложения «Фокус»

## 1. Цель

Развить уже опубликованный прототип приложения по скорочтению. Не создавать проект с нуля и не удалять функции, которые уже работают. До изменений изучить существующий репозиторий и проверить опубликованную архитектуру и сборку GitHub Pages.

### Что входит в этап

2. Игра на запоминание слов с настройкой количества слов и времени.
3. Новые тексты для каждой новой тренировки скорости чтения.
4. Загрузка собственных текстов в форматах EPUB, Word DOCX и TXT.

8. История и аналитика прогресса, сохраняемые локально.

## 2. Ключевое архитектурное решение: без авторизации и backend

На этом этапе **не реализовывать** регистрацию, вход, восстановление пароля, сервер, Supabase, облачную базу данных или облачную синхронизацию. Не создавать фиктивную авторизацию.

Приложение должно оставаться статическим сайтом, совместимым с существующим GitHub Pages workflow. Игровая логика выполняется в браузере.

### Где хранить данные
- `localStorage`: настройки, история завершённых тренировок, использованные встроенные тексты, ежедневные отметки букв и служебные небольшие данные.
- `IndexedDB`: извлечённые тексты пользовательских EPUB/DOCX/TXT, метаданные импортированных книг и прогресс чтения. Не хранить длинные книги целиком в `localStorage` из-за ограничений размера.
- Организовать хранение через отдельный модуль/адаптер, чтобы позже при необходимости можно было заменить реализацию хранения без переписывания игровых компонентов.
- Сохранить совместимость с существующими ключами `localStorage` и прежним форматом истории. Перед изменением посмотреть, какие данные уже используются. Не удалять старую историю автоматически; при необходимости добавить безопасную миграцию с сохранением исходных данных.
- Ясно обозначить в интерфейсе/README ограничение: результаты доступны в том же браузере на том же устройстве; после очистки данных сайта или смены браузера они могут потеряться. Между устройствами данные не синхронизируются.
- Добавить экспорт истории/настроек в JSON как полезную функцию резервной копии, если это удаётся сделать без риска для основной поставки. Импортировать только файлы ожидаемого формата с проверкой структуры и версии. Если экспорт/импорт не входит в текущий объём, явно указать это в итоговом отчёте.

## 4. Тест Мюнстерберга

### 4.1. Сценарий

Добавить отдельный экран «Тест Мюнстерберга» и карточку/ссылку на главной. До начала пользователь выбирает сложность. После нажатия «Начать» показывается массив буквенного шума; спрятанные слова не должны выделяться, отделяться пробелами или пунктуацией. Пользователь ищет слова и вводит их, разделяя пробелами, запятыми, точками с запятой или переносами строк. Кнопка «Проверить результат» завершает тест.

### 4.2. Уровни

| Сложность | Количество строк | Количество целевых слов |
|---|---:|---:|
| Лёгкий | 30 | 5 |
| Средний | 40 | 8 |
| Сложный | 50 | 11 |
| Эксперт | 60 | 15 |

Для лёгкого уровня использовать пять простых и максимально распространённых русских слов. Для всех уровней использовать разные целевые слова в рамках одного теста. Каждая строка ориентировочно 28 букв; строка должна сохраняться как единая логическая строка на экране. Адаптивно уменьшать моноширинный шрифт при узком экране, не допускать обрезания текста и горизонтального скролла по возможности.

### 4.3. Генерация и проверка

- Использовать встроенный словарь минимум из 150 распространённых русских слов, преимущественно простые существительные и общеупотребительные слова. Не использовать имена собственные, оскорбления и редкие термины.
- Целевые слова должны быть непрерывной последовательностью кириллических букв, спрятанной внутри случайного шума; длина строк и количество строк соответствуют выбранному уровню.
- Запуск каждого теста генерирует новый шум и новый набор слов; без повтора слов внутри одного теста.
- Не показывать целевые слова до завершения проверки.
- Нормализовать ввод: нижний регистр, очистка краевой пунктуации, удаление пустых токенов. Для этого теста `ё` и `е` допускается считать эквивалентными.
- Один и тот же правильный ответ засчитывается один раз. Слова, которых нет среди целей, показывать отдельно как лишние/ошибочные ответы.
- Генератор и функцию проверки вынести из UI в отдельные функции и покрыть тестами.

### 4.4. Результаты

Показать сложность, время выполнения, число найденных слов из общего количества, процент выполнения, найденные слова, пропуски и лишние ответы. Сохранять завершённый результат в локальной истории. Не отмечать незавершённый тест как завершённый.

## 5. Игра на память слов

### 5.1. Настройки

Перед стартом пользователь выбирает:
- количество слов — целое число от 5 до 50;
- время запоминания — 1, 2 или 3 минуты.

Показывать выбранные параметры и проверять корректность значений.

### 5.2. Процесс игры

1. После нажатия «Начать» сгенерировать список уникальных слов и показать его вертикальным столбцом.
2. Одновременно запустить обратный отсчёт выбранного времени.
3. Оставшееся время вычислять по временным меткам, чтобы переключение вкладки не замедляло таймер.
4. По завершении времени сразу скрыть все слова и показать поле ввода.
5. Пользователь вводит все слова, которые запомнил, через пробелы, запятые, точки с запятой или переносы строк и нажимает «Проверить».
6. До проверки не показывать исходный список повторно. После проверки показывать число и процент верных ответов, правильно вспомненные слова, забытые слова и лишние/неверные ответы.

### 5.3. Словарь и новизна

- Встроенный словарь минимум из 200 распространённых русских слов.
- В одном раунде не должно быть одинаковых слов.
- Для новых раундов создавать новую случайную комбинацию; не повторять точный набор из последних 20 игр, если доступных комбинаций достаточно.
- Не использовать API, нейросеть или backend для получения слов.
- Нормализовать ответы без учёта регистра и краевой пунктуации; `ё` и `е` допускается считать эквивалентными.

### 5.4. Таймер, результаты и история

Таймер должен останавливаться при завершении этапа запоминания и не сбиваться при переключении вкладки. Если страница перезагрузилась в середине игры, не сохранять сессию как завершённую; по возможности восстановить незавершённый этап или безопасно предложить начать заново. Завершённый результат сохранять с числом слов, временем запоминания, верными, пропущенными и лишними ответами, длительностью и временем завершения.

## 6. Тексты для чтения и импорт собственных книг

### 6.1. Встроенные тексты для проверки скорости

- Встроить библиотеку минимум из 30 оригинальных текстов на русском языке по темам науки, технологий, природы, истории, повседневной жизни, культуры, путешествий, привычек и обучения.
- Ориентир по объёму каждого текста: 300–700 слов, если текущий дизайн это позволяет.
- Не копировать защищённые авторским правом литературные произведения; использовать оригинальные тексты.
- Каждая новая тренировка скорости чтения должна выбирать ещё не использованный встроенный текст, пока есть доступные. Хранить использованные ID между открытиями сайта.
- После исчерпания показывать честное сообщение и действие «Сбросить историю использованных текстов». Не объявлять старый текст новым.
- Выбор следующего встроенного текста не должен зависеть от внешних API.

### 6.2. Форматы файлов

В разделе «Мои книги» добавить импорт локального файла:
- `.epub` — электронная книга EPUB;
- `.docx` — документ Microsoft Word современного формата;
- `.txt` — обычный текст, сохранить поддержку, если она уже есть.

Старый бинарный формат Word `.doc` не считать поддержанным в MVP; если его выбрали, показать понятное сообщение, что нужно сохранить файл как `.docx` и загрузить снова.

### 6.3. Парсинг и безопасность

- Обрабатывать файл непосредственно в браузере на устройстве пользователя. Не отправлять книгу на сервер и не использовать внешние API.
- До добавления зависимостей проверить текущий package manager и существующие библиотеки. Для DOCX можно использовать совместимую библиотеку извлечения текста, например Mammoth; для EPUB — проверенную библиотеку EPUB/ZIP-парсинга. Не устанавливать набор конкурирующих библиотек без необходимости.
- Для EPUB извлекать разделы в последовательности spine/оглавления, где это возможно; для DOCX сохранять абзацы и заголовки насколько позволяет парсер. Преобразовывать результат в безопасный текст; не вставлять непроверенный HTML напрямую в DOM.
- Показать прогресс загрузки/обработки, имя и размер файла, понятную ошибку для повреждённого или неподдерживаемого файла, пустого документа или ошибки парсинга.
- Ввести разумное ограничение размера файла, например 30 МБ, и объяснить его в интерфейсе.
- Сохранять метаданные и извлечённый текст пользовательской книги в IndexedDB. В LocalStorage хранить только компактные настройки/историю. После обновления страницы пользователь должен увидеть импортированную книгу и иметь возможность продолжить чтение на этом же устройстве/в том же браузере.
- Не дублировать одну и ту же книгу бесконечно: сверять ID/имя + размер и/или хеш содержимого; позволить удалить книгу из локальной библиотеки.

### 6.4. Чтение импортированной книги

- В разделе «Мои книги» показывать список импортированных книг, имя, прогресс и действие «Продолжить».
- Если EPUB содержит главы, предоставить навигацию по главам. В остальных случаях разбить извлечённый текст на удобные для чтения фрагменты, не теряя слова и порядок.
- Сохранять последний прочитанный раздел/позицию в IndexedDB.
- Не заставлять библиотечную книгу проходить правило уникальности встроенных текстов: книга принадлежит пользователю, он может продолжать её читать. Правило «всегда новый текст» применяется к встроенным тренировочным текстам.
- Для измерения скорости использовать количество слов в выбранном фрагменте и время от «Начать» до «Завершить чтение». Ясно показать, что расчёт приблизительный и зависит от того, действительно ли пользователь дочитал весь отображаемый фрагмент.

## 7. Таблицы Шульте

### 7.1. Тип содержимого и размеры

Сохранить все существующие режимы, добавить русские буквы. Поддержать сетки 5×5 и 7×7.
- **Числа:** текущая логика остаётся без регрессий.
- **Латиница:** текущая логика остаётся без регрессий.
- **Кириллица 5×5:** выбрать 25 уникальных букв из полного русского алфавита из 33 букв, включая `Ё`; определить целевой порядок по русскому алфавиту и перемешать расположение на сетке.
- **Кириллица 7×7:** ячеек 49, а букв 33. Использовать все 33 буквы включая `Ё` плюс 16 уникальных двухбуквенных кириллических токенов. Все 49 целей должны быть уникальными; показывать однозначный порядок поиска и визуально не обрезать двухбуквенные токены.

Правильное нажатие продвигает цель, неправильное — учитывается как ошибка. Генерировать новые расположения при новой сессии.

### 7.2. Цвета

Добавить переключатель:
- «Чёрно-белый» — все символы одного контрастного цвета;
- «Цветной» — символы получают цвета из заранее определённой палитры.

Настройка применяется к числам, латинице и кириллице и сохраняется для следующих тренировок. Цвет не меняет логику очередности и подсчёт результата. Контраст должен оставаться читаемым; цвет не должен быть единственным способом обозначения правильности.

## 8. Мнемотаблица 5×5: запомнить форму, цвет и положение

### 8.1. Идея

Создать отдельную игру «Мнемотаблица». Пользователь видит поле 5×5 с разноцветными элементами, запоминает положение каждого элемента и его цвет. После окончания времени запоминания элементы превращаются в чёрно-белые карточки в перемешанном наборе. Пользователь должен восстановить исходные позиции на поле 5×5 и выбрать для каждого элемента исходный цвет.

Это задание одновременно проверяет зрительную память на **положение + символ/форму + цвет**.

### 8.2. Настройки и уровни

Перед стартом пользователь выбирает сложность и время запоминания от 1 до 5 минут включительно.

| Уровень | Активных элементов | Палитра цветов | Состав элементов |
|---|---:|---:|---|
| Лёгкий | 9 | 3 цвета | Различающиеся геометрические фигуры |
| Средний | 16 | 4 цвета | Фигуры + русские буквы |
| Сложный | 25 | 6 цветов | Фигуры + русские буквы + символы |
| Эксперт | 25 | 8 цветов | Все типы, в том числе визуально похожие элементы |

Поле всегда имеет размер 5×5; незанятые клетки на лёгком и среднем уровнях остаются пустыми и должны быть восстановлены как пустые. Цвета должны иметь названия/подписи в интерфейсе, а не только визуальный кружок.

### 8.3. Фаза запоминания

- После нажатия «Начать» сгенерировать уникальный набор элементов и случайно разместить их по клеткам.
- Каждый элемент имеет однозначный вид: геометрическая фигура, кириллическая буква или отдельный символ. В одном раунде не повторять один и тот же знак/глиф, чтобы задача не имела неоднозначных решений.
- Каждый элемент окрашен одним цветом выбранной палитры.
- Запустить обратный отсчёт выбранных 1–5 минут. Рассчитывать время через временные метки; не сбивать таймер при переключении вкладки.
- По достижении нуля сразу скрыть цветное исходное поле и перейти к фазе восстановления. Не оставлять доступного действия для просмотра исходного поля после окончания.

### 8.4. Фаза восстановления

- Показать пустую сетку 5×5 и набор тех же элементов в чёрно-белом виде, перемешанных в случайном порядке.
- Пользователь помещает каждый элемент в ту клетку, где он находился изначально, и назначает цвет из палитры.
- На iPad управление должно быть удобно без мыши: поддержать схему «выбрать элемент → выбрать клетку»; drag-and-drop может быть дополнительным способом, но не единственным.
- Разрешить исправлять выбор, убирать элемент из клетки и перемещать его до проверки.
- Проверять два независимых аспекта: правильно ли размещён элемент и верно ли выбран его цвет. Пустые клетки тоже должны учитываться при итоговой оценке.
- Кнопка «Проверить» доступна после явного подтверждения пользователя. Если некоторые элементы не размещены, попросить подтвердить проверку неполного ответа.

### 8.5. Результат и хранение

Показать исходное поле рядом с ответом пользователя (или последовательно на мобильном экране), количество правильных позиций, количество правильно угаданных цветов, общий процент восстановления и список ошибок. Сохранять уровень, число элементов, время запоминания, длительность фазы восстановления, точность позиций, точность цветов и дату в локальной истории. При старте нового раунда генерировать новый набор, положение и цвета.

## 9. Алфавитная игра на ассоциации «От А до Я»

### 9.1. Алфавит и режимы

Поддержать все 33 буквы русского алфавита, включая `Ё`, `Ъ`, `Ы`, `Ь`.

Два способа запуска:
1. **Последовательно:** прохождение букв по порядку от А до Я. Отображать текущую букву и общий прогресс.
2. **Выбрать букву:** пользователь самостоятельно выбирает любую букву, которая ещё доступна для прохождения сегодня.

Если буква уже завершена сегодня в любом режиме, она считается завершённой для этого локального дня и не запускается повторно. При последовательном прохождении уже завершённая через ручной выбор буква отмечается выполненной и не должна блокировать переход к следующим буквам.

### 9.2. Категории

Для каждой выбранной буквы пользователь последовательно заполняет по одному ответу на каждую из 12 категорий:
1. Животное.
2. Птица.
3. Растение.
4. Автомобиль (марка или модель).
5. Предмет одежды.
6. Известная личность.
7. Поэт или писатель.
8. Страна.
9. Город.
10. Река или океан.
11. Женское имя.
12. Мужское имя.

### 9.3. Поэтапный интерфейс

- Показывать по одной карточке категории за раз: название категории, выбранная буква, поле ввода и кнопки «Далее»/«Пропустить».
- Таймер прямого отсчёта начинается с `00:00` при начале первой карточки и заканчивается только после ответа/пропуска последней карточки и завершения раунда.
- После отправки ответа переходить к следующей категории. Показывать прогресс, например «4 из 12».
- Проверять, что первое значимое кириллическое буквенное значение введённого слова соответствует выбранной букве. Если не соответствует, показать ошибку и предложить исправить либо пропустить. Не позволять пустому ответу незаметно засчитываться как ответ.
- Для букв, с которых трудно или невозможно подобрать ответ в конкретной категории (особенно `Ё`, `Й`, `Ъ`, `Ы`, `Ь`), обязательно дать возможность явно нажать «Пропустить». Не требовать невозможного ответа, иначе прохождение может зависнуть.
- Не подключать внешний API для проверки смысла ответов. На этом этапе проверять букву в начале слова, сохранять текст ответа и явно не заявлять об автоматической смысловой валидации принадлежности к категории.
- Последняя карточка должна позволять завершить раунд, даже если некоторые поля пропущены.

### 9.4. Ежедневное ограничение

- После завершения раунда конкретную букву нельзя запустить повторно до следующего локального календарного дня на этом же устройстве/в этом же браузере.
- Сохранять дату завершения по каждой букве в `localStorage`; использовать локальную дату устройства в формате `YYYY-MM-DD`.
- На карте алфавита показывать доступные буквы и буквы, уже завершённые сегодня, с сообщением «Доступно завтра» и датой/понятным временем разблокировки.
- Обновление страницы не должно обнулять таймер активной игры или позволять заново начать активную букву. Сохранять черновые ответы, категорию и метку времени начала; при возвращении возобновлять активную сессию с учётом фактически прошедшего времени. Завершённую букву блокировать только после финального завершения, а не при простом открытии экрана.
- В один и тот же день пользователь может проходить другие ещё не завершённые буквы. Запрещён повтор именно уже завершённой буквы.
- Так как авторизации и сервера нет, ограничение действует только в текущем браузере/устройстве и может быть сброшено очисткой данных сайта. Не заявлять, что это защищённое серверное ограничение.

### 9.5. Результат

По завершении показать букву, общее время, количество заполненных и пропущенных категорий, список ответов и предупреждения о словах, которые не начинались на нужную букву. Сохранять локально дату, букву, ответы, пропуски и длительность. Обновить аналитику прогресса по алфавитной игре.

## 10. Единая история и аналитика

Сохранить историю существующих видов тренировок и расширить её для:
- `reading` — скорость чтения, число слов, время, ID встроенного текста или локальной книги;
- `schulte` — размер, режим символов, цветовой режим, длительность, ошибки;
- `munsterberg` — сложность, строки, целевые слова, правильные/пропущенные/лишние;
- `memory_words` — количество слов, время на запоминание, правильные/пропущенные/лишние;
- `mnemo_grid` — уровень, число элементов, время запоминания, точность позиций и цветов;
- `alphabet_association` — буква, длительность, заполненные/пропущенные категории.

На экране «Мой прогресс» показывать общее число завершённых тренировок, последние результаты и отдельные метрики по каждому типу. Не сравнивать несопоставимые метрики в одном рейтинге. Отображать дружелюбное пустое состояние, если истории нет. Не показывать выдуманные результаты.

## 11. Общие требования к интерфейсу и качеству

- Язык интерфейса — русский.
- Сохранить существующий стиль и навигацию, не переписывать сайт без необходимости.
- Поддерживать Safari на iPad и современные десктопные браузеры. Элементы управления должны быть удобны для касаний.
- Таймеры не должны ускоряться/замедляться из-за фоновой вкладки; вычислять состояние через timestamp и при возвращении обновлять отображение.
- Во время завершённой сессии результат сохранять один раз, избегая дублей при повторном нажатии.
- При ошибках импорта показывать понятные сообщения; не ломать остальную работу приложения.
- Обеспечить доступность: подписи полей, различимый фокус, достаточный контраст, понятные состояния кнопок.
- Не добавлять регистрацию, сервер, Supabase, аналитику сторонних сервисов или внешние API.

## 12. Критерии приёмки

### Сохранение и архитектура
- [ ] Приложение остаётся статическим и работает на GitHub Pages.
- [ ] Нет экранов/вызовов регистрации, логина, Supabase или внешнего backend.
- [ ] Прежние функции первого этапа не регрессировали.
- [ ] История и настройки переживают обычное обновление страницы в том же браузере.
- [ ] Длинный текст книги хранится в IndexedDB, а не полностью в localStorage.

### Мюнстерберг
- [ ] Уровни точно соответствуют таблице 30/5, 40/8, 50/11, 60/15.
- [ ] Слова спрятаны внутри непрерывного шума и не выделены.
- [ ] При каждом запуске генерируются свежий шум и новый набор целей.
- [ ] Правильные ответы, повторы, пропуски и лишние слова подсчитываются корректно.

### Игра на память
- [ ] Принимается 5–50 слов и 1/2/3 минуты.
- [ ] Слова показываются столбцом, исчезают по окончании отсчёта и недоступны до отправки ответа.
- [ ] Результат показывает верные, забытые и лишние слова.
- [ ] В раунде нет дублей, а наборы раундов меняются.

### Чтение и импорт
- [ ] Встроенных оригинальных текстов не менее 30; повторов нет до исчерпания библиотеки.
- [ ] Можно загрузить EPUB, DOCX и TXT.
- [ ] Файлы обрабатываются локально; сетевой upload книги отсутствует.
- [ ] Импортированную книгу можно открыть после обновления страницы в том же браузере.
- [ ] Неподдерживаемый `.doc`, повреждённые и пустые файлы обрабатываются понятным сообщением.

### Шульте
- [ ] Есть режимы числа, латиница, кириллица; размеры 5×5 и 7×7.
- [ ] В кириллическом режиме учитывается `Ё`; все цели уникальны.
- [ ] Для 7×7 кириллицы имеется 49 уникальных целей.
- [ ] Цветной и чёрно-белый режим работают во всех типах контента.

### Мнемотаблица

- [ ] Уровни: 9/16/25/25 элементов с палитрами 3/4/6/8 цветов.
- [ ] По окончании таймера цветное поле скрывается и остаётся только чёрно-белый набор.
- [ ] На iPad можно восстановить расстановку и выбрать цвет без мыши.
- [ ] Результат раздельно оценивает расположение и цвет.

### Алфавитная игра
- [ ] Доступны все 33 буквы, включая `Ё`, `Ъ`, `Ы`, `Ь`.
- [ ] Есть последовательный режим и ручной выбор буквы.
- [ ] Есть 12 последовательных карточек категорий.
- [ ] Прямой таймер начинается на первой карточке и заканчивается после последней.
