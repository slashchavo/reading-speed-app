# TECH_SPEC.md — техническое задание MVP

## 1. Цель

Создать работающий адаптивный веб-прототип приложения «Фокус» с базовыми функциями таблиц Шульте, чтения текста и локальной истории результатов.

## 2. Технологии и ограничения

- Vite.
- React.
- TypeScript в строгом режиме.
- Обычный CSS без обязательного UI-фреймворка.
- Без backend, авторизации и внешних API.
- `localStorage` используется для хранения настроек и завершённых занятий.
- Все зависимости должны быть необходимыми; не добавлять библиотеки без объяснения причины.
- Команды запуска и сборки фиксируются в `README.md` проекта.

## 4. Навигация

Четыре раздела:
- Главная.
- Шульте.
- Чтение.
- Прогресс.

На широком экране допустима боковая навигация или верхнее меню. На мобильном экране навигация должна оставаться доступной и не перекрывать содержимое.

## 5. Функциональные требования: таблица Шульте

### Настройки перед стартом
- Размер: 5×5 или 7×7.
- Содержимое: числа или буквы.
- Кнопка «Начать тренировку».

### Создание сетки
- Для 5×5 с числами: уникальные значения 1–25.
- Для 7×7 с числами: уникальные значения 1–49.
- Для 5×5 с буквами: A–Y.
- Для 7×7 с буквами: A–Z, затем AA–AW.
- Позиции элементов случайны при каждом новом старте.
- Внутри одной сетки нет дубликатов.

### Игровой процесс
- До старта таймер не идёт.
- После нажатия «Начать» запускается секундомер и появляется сетка.
- Приложение показывает целевой элемент, который пользователь должен нажать следующим.
- Нажатие правильного элемента увеличивает прогресс.
- Нажатие неправильного элемента увеличивает счётчик ошибок, но не меняет целевой элемент.
- После последнего правильного выбора секундомер останавливается, результат сохраняется.
- Пользователь видит итоговое время, ошибки и кнопку повторного запуска.
- При повторном запуске должна генерироваться новая перестановка.
- Уход со страницы во время незавершённой тренировки не должен сохранять её как завершённую.

### Важные технические детали
- Время вычисляется от временной метки старта, а не простым увеличением счётчика раз в секунду; так таймер не будет накапливать заметную ошибку при задержках вкладки.
- Все таймеры и подписки очищаются при размонтировании компонента.
- Генерация случайной перестановки должна быть вынесена в чистую функцию и проверяема отдельно.

## 6. Функциональные требования: чтение

### Источник текста
- Приложение содержит демонстрационный русский текст, доступный сразу после открытия.
- Пользователь может вставить текст в текстовое поле.
- Пользователь может загрузить `.txt` файл через стандартный выбор файла браузера.
- Если текст пустой или в нём нет слов, старт не разрешается; показывается понятная подсказка.
- На первом этапе PDF, DOCX и EPUB не поддерживаются.

### Сессия чтения
- Пользователь выбирает/вставляет текст.
- Пользователь может увеличить или уменьшить размер шрифта в разумных границах.
- При нажатии «Начать» фиксируется время начала.
- При нажатии «Завершить» фиксируется время окончания и рассчитываются длительность и слова в минуту.
- Длительность для расчёта не должна быть нулевой; если сессия короче одной секунды, показать корректную обработку, а не `Infinity` или `NaN`.
- «Сбросить» завершает текущий незаписанный сценарий и возвращает интерфейс в исходное состояние.
- Завершённый результат автоматически сохраняется один раз. Повторный рендер или повторное нажатие не должны создать дубликат записи.

### Расчёт
- Число слов рассчитывается после нормализации пробелов и разбиения непустого текста по пробелам/переносам строк.
- `wordsPerMinute = wordCount / (durationSeconds / 60)`.
- Отображать скорость целым числом слов/мин.
- Результат описывать как ориентировочную скорость, поскольку приложение не проверяет понимание текста.

## 7. Прогресс и хранение

### Модель данных

```ts
type SchulteSession = {
  id: string;
  type: 'schulte';
  completedAt: string; // ISO 8601
  durationSeconds: number;
  gridSize: 5 | 7;
  mode: 'numbers' | 'letters';
  mistakes: number;
};

type ReadingSession = {
  id: string;
  type: 'reading';
  completedAt: string; // ISO 8601
  durationSeconds: number;
  wordCount: number;
  wordsPerMinute: number;
};

type Session = SchulteSession | ReadingSession;
```

- Хранить массив завершённых сессий в `localStorage` под ключом `focus-app:sessions:v1`.
- Если `localStorage` пустой, приложение работает без ошибок с пустой историей.
- Если сохранённые данные повреждены или имеют неожиданный формат, приложение должно безопасно сбросить/игнорировать некорректные данные и не падать с белым экраном.
- Ошибки чтения/записи локального хранилища обрабатывать аккуратно; в случае невозможности сохранить результат показать предупреждение пользователю.
- Настройки интерфейса можно хранить под отдельным ключом `focus-app:settings:v1`.
- Авторизация и межустройственная синхронизация отсутствуют.

### Страница прогресса
- Показывать завершённые тренировки от новых к старым.
- Показывать тип, локальную дату/время, длительность и результат.
- Для чтения показывать слова/мин; для Шульте — сетку и количество ошибок.
- При отсутствии истории показывать пустое состояние с CTA для первой тренировки.
- Главная страница рассчитывает общее число сессий и лучший результат чтения по сохранённым данным. Не выводить фиктивные значения, если данных нет.

## 8. Состояния интерфейса

Каждый экран должен корректно обрабатывать:
- начальное состояние;
- загрузку/выбор пользовательского текста;
- активную тренировку;
- завершённую тренировку;
- пустую историю;
- ошибку локального хранения;
- слишком короткий или пустой текст.

## 9. Визуальные требования

- Чистый интерфейс с хорошей визуальной иерархией.
- Основной текст и кнопки контрастны и читаемы.
- Ячейки Шульте имеют достаточную площадь нажатия, особенно на мобильном экране.
- Не использовать цвет как единственный способ показать правильность/ошибку.
- Кнопки имеют видимые hover/focus/disabled-состояния.
- Поддерживать клавиатурную навигацию и видимый фокус.
- Не допускать горизонтальной прокрутки на ширине 360–390 px.
- Проверить макет как минимум на 390×844 и 1366×768 px.

## 10. Критерии приёмки

### Общие
- [ ] Проект запускается по команде, записанной в README.
