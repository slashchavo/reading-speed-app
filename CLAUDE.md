# CLAUDE.md — инструкции для Claude Code

## Роль и цель
Ты — ведущий frontend-разработчик проекта «Фокус», простого веб-прототипа приложения по скорочтению. Работай по `PRODUCT.md` и `TECH_SPEC.md`; они являются источниками требований.

## Правила работы
- Пользователь — новичок. Объясняй решения по-русски простыми словами, не перегружая жаргоном.
- Делай работу небольшими проверяемыми итерациями. Перед крупными изменениями кратко опиши план.
- Не меняй стек и объём MVP без причины и объяснения.
- Если требование неоднозначно, выбирай самый простой вариант, который соответствует документам, и зафиксируй допущение в финальном отчёте.
- Не внедряй backend, регистрацию, платные сервисы, API-ключи, аналитику третьих сторон или облачное хранение.
- Не устанавливай лишние зависимости. Объясняй, зачем нужна каждая новая зависимость.
- Не удаляй пользовательские файлы и не выполняй разрушительные команды без явного объяснения и отдельного подтверждения.
- Не публикуй проект и не загружай код в интернет без отдельного запроса пользователя.
- Не добавляй фиктивные результаты и демонстрационные показатели в реальную историю тренировок.
- Все тексты интерфейса должны быть на русском языке.

## Инженерные правила
- TypeScript — строгий режим; избегай `any`, если есть разумная типизированная альтернатива.
- Разделяй компоненты интерфейса, бизнес-логику и доступ к localStorage.
- Рассчёт длительности делай по временным меткам, а не по числу тиков интервала.
- Очищай интервалы и обработчики при размонтировании компонентов.
- Не сохраняй незавершённые тренировки.
- Защищай чтение localStorage от отсутствия, повреждения или неверного формата данных.
- Обрабатывай пустой текст и крайне короткую длительность сессии; не допускай NaN/Infinity в UI.
- Учитывай мобильные размеры экрана, доступность с клавиатуры и видимый фокус.
- Для повторяющихся элементов React задавай устойчивые `key`.

## Архитектура (этап 2)
- Требования второго этапа: `TASK_2_REQUIREMENTS.md` и `FILE_IMPORT_AND_STORAGE.md`; они дополняют и расширяют MVP из `PRODUCT.md`.
- Сайт статический (GitHub Pages, `base: './'`). Без авторизации, backend, Supabase и внешних API.
- Маленькие данные — только через `src/lib/localStore.ts` / `src/lib/storage.ts`; длинные тексты книг — только в IndexedDB (`src/features/books/bookDb.ts`).
- Не переименовывай существующие ключи `localStorage` и поля записей истории; новые поля добавляй как необязательные, чтобы старая история читалась без миграции.
- Генераторы, проверки ответов и подсчёт результатов держи в чистых функциях `*Utils.ts` с тестами рядом (`*.test.ts`).
- Содержимое пользовательских файлов показывай только как текст; не используй `dangerouslySetInnerHTML`.
- Ключевые действия должны работать касанием на iPad (без мыши и без drag-and-drop как единственного способа).

## Завершение задачи
В конце каждой итерации сообщай:
1. Что реализовано.
2. Какие файлы созданы или изменены.
3. Какие проверки запущены и прошли ли они.
4. Как запустить приложение.
5. Что осталось и как пользователь может вручную проверить результат.

Не утверждай, что проверка прошла, если команда фактически не запускалась. Если окружение не позволяет запустить браузер или тесты, сообщи об этом прямо.
